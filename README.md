# Codex Session Tabs

English · [Русский](README.ru.md)

**Fork of [kasiaalena/codex-session-tabs](https://github.com/kasiaalena/codex-session-tabs).** It adds Intel Mac support (official Codex 26.1007.21434), starts quietly without a setup reminder and fixes several issues; see the [CHANGELOG](CHANGELOG.md). It keeps the extension ID `kasiaalena.codex-session-tabs`, so it replaces the original installation and keeps its state.

Independent Codex editor tabs, an open-sessions sidebar, short titles and orange completion indicators for VS Code. An unofficial companion to the OpenAI Codex extension; this project is not affiliated with or supported by OpenAI.

**Supported setup:** local VS Code on macOS, Python **3.9+** and the system `/usr/bin/sqlite3`. Compatibility profiles: Intel (`darwin-x64`) with official Codex **26.1007.21434**, tested on an Intel Mac in this fork; Apple silicon (`darwin-arm64`) with official Codex **26.1021.22027**, unchanged from upstream, where it was tested. This fork has not been run on Apple silicon hardware. Tested with VS Code **1.145.0**. The manifest accepts VS Code 1.106+, but older releases, Windows, Linux and remote extension hosts have not been verified.

**Preview 0.4.5 (fork).** Installers: `codex-session-tabs-0.4.5-darwin-arm64.vsix` for Apple silicon and `codex-session-tabs-0.4.5-darwin-x64.vsix` for Intel. Download them from this fork's [Releases](https://github.com/Haman888/codex-session-tabs/releases), or build them from source. The package ID is `kasiaalena.codex-session-tabs`. An earlier local installation with a different ID needs a separate state transfer before replacement. This build does not transfer that state automatically. Keep the earlier installation until a transfer has been prepared and checked.

## Features

- **Open sessions** contains only Codex tabs open in the current window. Select an entry to switch tabs; its close action closes the tab.
- **History** contains saved conversations without an open tab. Select one to open its transcript and move it into Open sessions. The clock button also opens a searchable history popup.
- **New tab** creates an independent draft. Temporary labels are `New chat 1`, `New chat 2`, etc. Numbering restarts after a window restart or reload and skips numbers used by open tabs, including restored background tabs.
- After the first message, the tab uses the conversation name generated by Codex. Automatic labels are limited to five words and 36 characters; the companion does not call a model to create names.
- Rename a tab or sidebar entry from its context menu. Saved conversations are renamed through Codex's own API. Manual names can contain up to 120 characters.
- A spinning indicator in the open-sessions sidebar shows a reply in progress. It changes to an orange dot when a background reply finishes. Running status uses live Codex events and is not replayed from disk after a restart.
- An orange dot marks a background tab when its reply finishes, on both the editor icon and the sidebar entry. Reading that ready, visible tab in the focused VS Code window for about a second clears it. Restoring a tab alone does not clear unread indicators.

Closing a saved tab does not delete or archive the conversation. An empty draft has no saved conversation until its first message.

## Language

Use the globe button or **Codex: Language / Язык** in the Command Palette. Choose **English**, **Русский**, or **Follow VS Code**. The default follows VS Code; other languages use English. The setting is `codexSessionTabs.language`: `auto`, `en`, or `ru`.

The selection immediately changes the companion's commands, menus, sections, notifications, dates and automatic empty-draft labels. Conversation names and manual labels are preserved. It does not change the language of VS Code or the official Codex chat. Labels in VS Code's Settings editor follow VS Code's display language. Existing notifications retain their original language.

## Install and set up protection

1. Install the official Codex extension (`openai.chatgpt`) and sign in to your own account.
2. Download the matching VSIX from Releases, or build it as described below. Run **Extensions: Install from VSIX…** in VS Code and select the file.
3. Run **Codex: Check and update Codex** and confirm the dialog that names the download size. The official extension directory is detected automatically.
4. Wait for verification, then review the separate installation confirmation. The supported version may be older than the latest Marketplace release; the dialog names the version being installed.
5. After current replies finish, run **Developer: Reload Window**. The companion never reloads the working window without your action.

Setup downloads the approved official package, about **400 MB**, verifies its SHA-256, prepares the adapter and tests it in a separate VS Code window. Allow extra disk space for extraction and verification. The procedure creates CPU and disk load; run it when other work can pause. A second VS Code dock icon may appear temporarily. The test profile has empty history and sends no model messages. The test window closes automatically.

After a successful check, the recovery package is saved **before** installation is confirmed. Cancelling that final dialog keeps the package and leaves the installed Codex unchanged. Later, **Codex: Restore verified Codex** can install it without repeating the download and test.

Local VSIX installation pins that official Codex version and disables its ordinary automatic updates. Other extensions retain their settings. An explicit manual Update or Update All can replace the adapter. Unknown Codex releases are not automatically approved; a new compatibility profile requires verification.

Check the downloaded installer against `SHA256SUMS.txt` from the same release. In a terminal containing both files, run `shasum -a 256 -c SHA256SUMS.txt`.

## Recovery

The status-bar shield shows adapter health. Checks run at startup, when installed extensions change, and periodically. Recovery commands remain available if the official Codex interface cannot start.

**Codex: Restore verified Codex** checks the saved package and asks for confirmation before installation. Reload after replies finish. An existing working recovery is retained when a new candidate is checked; a failed check does not authorize installation.

Recovery is tied to the companion build. Upgrading the companion can require another verification even when the official Codex version is unchanged. An intact package for an older companion is not proof that the new combination works. Do not edit recovery receipts to bypass verification.

This fork shows no setup reminder: nothing is downloaded and no test window opens unless you run **Codex: Check and update Codex** and confirm the dialog. For errors, use the **Codex Session Tabs** Output channel. Avoid sharing raw reports that may include local paths or conversation names.

## History and privacy

The list reads local metadata from `~/.codex/state_*.sqlite` and `session_index.jsonl`; `CODEX_HOME` is supported. Transcript contents are not required for the list. The adapter does not pass prompts, replies or credentials to the companion. Saved names are written only on explicit rename through Codex's API.

History reads share a short cache. After a failure, the last successful list remains available and retries back off. **Codex: Refresh sessions** retries immediately. A read-only Python SQLite fallback is used if the system reader cannot open the database. An unavailable source is distinguished from an empty history.

The adapter modifies reviewed files in the installed official extension and keeps originals with checksums. It uses internal Codex interfaces, so compatibility with every future release cannot be promised. Unapproved versions and changed originals are refused.

OpenAI's extension and artwork are not included in this repository or companion VSIX. Indicator icons are derived locally from the installed extension. Original and patched official packages stay on the user's computer.

## Known harmless errors

The official Codex may log `fs/readFile` errors for `~/.codex/attachments/pasted-text-attachments.json` at startup. This comes from Codex itself, not from the companion, and is harmless — Codex creates the file on first use. Do not create it manually.

## Build and test

From the repository root, with Node.js 22+ and Python 3.9+:

```sh
npm test
npm run package
```

Packaging uses the Python standard library and downloads no build dependencies. Output: `dist/codex-session-tabs-0.4.5-darwin-arm64.vsix` on Apple silicon or `dist/codex-session-tabs-0.4.5-darwin-x64.vsix` on Intel. To build for the other processor, run `python3 scripts/package.py darwin-arm64` or `python3 scripts/package.py darwin-x64`.

`npm test` uses small artificial fixtures in system temporary storage. It does not use real Codex history or launch GUI windows. The runtime protection check uses a separate empty profile.

The separate developer test `test/integration.js` requires at least three saved conversations and an isolated test window with a prepared copy of the official extension and adapter. Create a fresh private profile before starting that separate Code process:

```sh
export CODEX_TABS_TEST_USER_DATA="$(node -p "require('node:fs').mkdtempSync(require('node:path').join(require('node:os').tmpdir(), 'cst-integration-'))")"
```

Pass this exact directory as `--user-data-dir "$CODEX_TABS_TEST_USER_DATA"`, the prepared candidate directory as `--extensions-dir`, this repository as `--extensionDevelopmentPath`, and `test/integration.js` as `--extensionTestsPath`. Open no workspace folder. The test verifies both Test mode and the actual profile storage before writing its reports or changing editors; it refuses ordinary launches and mismatched profiles. It checks that three saved conversations exist before closing editors in the isolated window. Never use your working profile for this test.

Reports and optional screenshots use one new private `codex-tabs-report-*` directory inside that temporary profile (directory mode 0700, files 0600); the path is printed when the run finishes. `CODEX_TABS_TEST_REPORT` no longer redirects output. The visual helper uses the same private output writer and has no shared default path. Tests check tabs, history, titles, manual rename and simulated completion without sending model messages. These developer reports can still contain real names and paths: keep them private and out of publications.

Large extension copies, VSIX extraction and GUI profiles must stay outside open workspaces, preferably in system temporary storage. A separate VS Code profile does not isolate filesystem watcher load; `.gitignore` does not disable those watchers.

## Advanced manual check and clean removal

Normal setup and recovery detect the directory automatically. For a manual check, make the VS Code `code` command available in your terminal PATH, then run from the matching companion source directory:

```sh
CODEX_EXTENSION_DIR="$(code --locate-extension openai.chatgpt)"
python3 scripts/native_adapter.py --extension-dir "$CODEX_EXTENSION_DIR" --check
```

This returns the actual directory without assuming a platform suffix. With a custom extensions directory or profile, pass the same options used to launch VS Code. If the official extension is not found, stop here. The adapter picks the compatibility profile whose reviewed files are on disk; for a package built for another processor, add `--platform darwin-arm64` or `--platform darwin-x64`.

For clean removal, first restore the original official files:

```sh
python3 scripts/native_adapter.py --extension-dir "$CODEX_EXTENSION_DIR" --restore
```

Then uninstall **Codex Session Tabs** in VS Code and reload after current replies finish. The script checks original and patched files and refuses to overwrite unrelated changes. Use the adapter tool matching the installed companion: the new layout will not overwrite an older one without its verified backup.
