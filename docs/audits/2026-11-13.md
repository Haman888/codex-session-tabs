# Codex Session Tabs — аудит и восстановление, 13.11.2026

Дополнение после этого аудита: поддержка актуального Codex реализована в
0.6.5; результаты — в [отдельном отчёте](2026-11-13-latest-codex.md).

## Подтверждённая причина сбоя

Проверено по локальному журналу VS Code `20261111T195034/sharedprocess.log`:
13.11.2026 установка `openai.chatgpt` 26.1111.21308 прошла с `pinned:false`;
VS Code пометил прежнюю 26.1007.21434 удалённой. Журнал не устанавливает,
кто инициировал обновление — пользователь, автоматическое обновление или иной механизм.

В `window2/exthost/openai.chatgpt/Codex.log`, строки 395–397, три панели
26.1111.21308 завершились `renderer_ready_timeout`, `timeoutMs=30000`,
`receivedWebviewMessage=false`. В реестре расширений новая сборка имела
`source:gallery`, `pinned:false`; дополнение 0.6.3 — `source:vsix`, `pinned:true`.
`compatibility.json` дополнения поддерживает Intel-сборку 26.1007.21434,
а новая установленная версия не имеет профиля адаптера.

Это два связанных ограничения: обновление заменяет модифицированные файлы
официального расширения, а восстановленные панели снова получают штатный
30-секундный watchdog. Высокая нагрузка на компьютер наблюдалась (`code --status`),
но её вклад в конкретный таймаут отдельно не измерялся.

## Воспроизведённые дефекты, исправленные в 0.6.4

| Приоритет | Дефект | Доказательство и исправление |
| --- | --- | --- |
| P1 | Команды открывают редактор с неподдерживаемым, отсутствующим или изменённым адаптером | Новый тест через зарегистрированные команды до исправления открыл 3 редактора вместо 0. `ensureCodex()` теперь проверяет здоровье адаптера до активации/открытия. После восстановления здоровья команды снова работают. |
| P1 | Два окна одновременно восстанавливают устаревший lock обновления | Детерминированное чередование двух операций дало 2 одновременно выполняемых критических участка. Проверка и перенос старого lock теперь защищены отдельным эксклюзивным `.reclaim`. Регрессия подтверждает максимум 1 и возможность следующей операции. |
| P2 | Python-загрузчик удаляет существующий файл при ошибке открытия и оставляет пакет с неверной суммой | До исправления тест завершился `Pre-existing recovery was deleted`. Владение загрузкой теперь определяется успешным созданием и парой device/inode; чужой файл сохраняется, собственный отклонённый пакет удаляется. |

Регрессии находятся в `test/quiet-ux.test.js`, `test/updates.test.js`,
`test/download-cleanup.test.js`. Все три сначала воспроизвели ошибку,
затем прошли с исправлением. Исходный набор 0.6.3 состоял из 108 проходящих
тестов и эти случаи не выявлял. Полный набор 0.6.4: 111 passed, 0 failed,
0 skipped, `npm test` завершился с кодом 0.

## Проверка в настоящем VS Code

Проверена связка с Codex 26.1007.21434 в отдельном временном профиле,
с отдельным `CODEX_HOME`, без копирования пользовательских токенов и истории.
Первый запуск завершил 8/8 проверок за 48 328 мс:

1. Изоляция профиля и проверка установленного адаптера.
2. Две команды штатного New Chat создают разные постоянные ресурсы вкладок.
3. Обе панели подтверждают `renderer_ready`.
4. Переключение английского/русского языка.
5. Вкладки не являются preview-вкладками.
6. Переименование отражается в заголовке.
7. Синтетическое завершение ответа отмечается индикатором.
8. Выбор вкладки в окне с фокусом снимает индикатор.

Это проверка интерфейса и маршрутизации. Настоящий запрос к модели,
восстановление пользовательского диалога и пользовательское рабочее окно
после перезагрузки этим тестом не подтверждены. В профиле без авторизации
зарегистрированы HTTP 401; выдавать его журнал за полностью безошибочный нельзя.

Пакет восстановления Codex:
`openai.chatgpt-26.1007.21434-darwin-x64-session-tabs.vsix`, SHA-256
`583ead48e18b0fd5370473ca5081c02221f3ce6f7c45485753a32cb4de25508e`.
Хеш патченного `out/extension.js` совпадает с профилем;
`session-tabs-native.cjs` совпадает с мостом дополнения.

После установки повторён тот же тест уже из каталога установленного дополнения
0.6.4: 8/8 проверок пройдены за 46 538 мс. Изменённые runtime-файлы на диске
сверены побайтно с исходниками. В реестре обе установки имеют `source:vsix`,
`pinned:true`: Codex 26.1007.21434 и Codex Session Tabs 0.6.4.
Рабочее окно продолжает использовать прежний загруженный код до Reload Window.
Для установленного helper-build сохранены `recovery.json`, пакет с проверенным
SHA-256 и `last-probe.json` в локальном globalStorage дополнения; вызов
`UpdateManager.recovery()` подтвердил пригодность копии. Итоговый отчёт
интеграционной проверки сохранён рядом: `2026-11-13-probe.json`.

## Следующие улучшения

- **P1 — поддержка актуального Codex: выполнено в 0.6.5.** Добавлен профиль
  26.1111.21308, пройдены отдельные GUI-проверки и проверка установленного пакета;
  результаты — в [отчёте](2026-11-13-latest-codex.md). Наличие `pinned:true`
  не доказывает невозможность последующего ручного обновления.
- **P2 — восстановление после обновления самого дополнения.** Сейчас квитанция
  recovery связана с `helperHash()` всех файлов, включая тексты и package.json.
  Даже косметический релиз делает её непригодной. Можно разделить отпечаток
  адаптера и интерфейса, но только с повторной проверкой совместимости;
  простое удаление проверки хеша недопустимо.
- **P2 — восстановление lock после аварийного завершения.** Новый `.reclaim`
  намеренно не удаляется другим окном автоматически. При обрыве владельца
  может понадобиться проверка процессов и ручное снятие блокировки. Дальнейшее
  улучшение — системная межпроцессная блокировка или безопасная процедура
  восстановления; повторять прежний check-then-rename нельзя.
- **P2 — память при большой истории.** `readSessionNames()` читает весь
  `session_index.jsonl` и затем разбивает его на строки. Полезны потоковое
  чтение и ограничение размера названий. Фактический перерасход памяти этим
  методом в текущем инциденте не измерялся.
- **P2 — сценарий обновления в интеграционных тестах.** Помимо чистого профиля
  проверять замену Codex при сохранённых вкладках, перезагрузку окна и отказ
  дополнения при неподдерживаемой версии. Текущая командная регрессия покрывает
  отказ до открытия, но не восстановление редакторов самим VS Code.

## Безопасность и границы проверки

Проверены код загрузки/распаковки/установки, мост, чтение истории и тесты.
Существующие тесты проверяют контрольные суммы, подмену staged-пакета,
traversal/symlink/duplicate-записи VSIX, сохранность файлов при откате,
чтение SQLite в read-only и изоляцию тестового профиля. Это ограниченный аудит
исходного кода дополнения; аудит всего официального Codex, VS Code и всех
установленных расширений не выполнялся.
