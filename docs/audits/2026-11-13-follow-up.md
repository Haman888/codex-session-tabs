Проверены индикатор лимитов, нативный мост, управление вкладками и их состоянием, чтение истории, загрузка/проверка/установка обновлений и обратимый адаптер. Это аудит дополнения; весь код официального Codex и VS Code в него не входит.

## Подтверждённые ошибки: исправления 0.8.1

| Приоритет | Сценарий | Проявление до исправления |
| --- | --- | --- |
| P2 | Сбой чтения лимита, затем свежее уведомление | Глобальный флаг ошибки продолжал скрывать актуальный остаток до следующего успешного полного запроса. |
| P2 | Уведомление во время первоначального полного запроса | Весь полный ответ отбрасывался. Недостающая длительность недельного окна и другие лимиты не попадали в индикатор. |
| P2 | Новый процент получен, затем завершился старый запрос с ошибкой | Поздняя ошибка скрывала более свежие данные. |
| P2 | Недельный лимит сбросился; новое уведомление содержит только процент | Старое время сброса могло сохраниться вместо нового, оставляя актуальный остаток в состоянии «данные устарели». |

Причина — слишком крупная единица учёта порядка обновлений. Теперь ошибка привязана к отдельному лимиту, а порядок значений отслеживается отдельно для `usedPercent`, `windowDurationMins`, `resetsAt`. Полный ответ дополняет недостающие поля и не перезаписывает новые уведомления. Смена аккаунта по-прежнему отменяет применение старых ответов.

Это ошибки моей реализации 0.8.0. Добавлены четыре детерминированные регрессии. Первый вариант исправления учитывал порядок целого окна и ещё сохранял старое время сброса; дополнительный тест выявил это до установки. Итоговое исправление учитывает порядок каждого поля.

Отдельно исправлен порядок шагов GUI-теста: сброс состояния выполняется до ожидания запроса. Иначе сброс снова разрешал фоновый запрос из профиля без авторизации между подстановкой тестового процента и переключением вкладки. В первом GUI-прогоне восемь проверок прошли, проверка остатка после переключения вкладки завершилась ошибкой. Такой результат не использован для допуска установки.

- Нативный мост не изменён. Индикатор получает только числовые поля через прежнюю фильтрацию; внутренние счётчики порядка создаются после фильтрации и не принимаются из ответа сервера.
- Изменения не добавляют доступ к токенам авторизации, файлам переписок или новым сетевым адресам. Проверены границы авторизации, отображения данных, файловых операций и сети. Защита от ответов предыдущего аккаунта, контрольные суммы пакетов и проверки путей сохранены.

## Что улучшать дальше

1. **P2 — резерв после обновления самого дополнения.** `helperHash()` включает весь manifest и тексты. Проверенный резерв и обнаруженные профили перестают подходить после любого изменения сборки. Нужны отдельный отпечаток совместимости и проверяемая миграция квитанций; убирать проверку хеша нельзя. В текущей установке резерв перепроверяется вручную при выпуске.
2. **P2 — восстановление после аварии обновления.** Оставшийся `operation.lock.reclaim` требует проверки владельца и безопасного снятия блокировки. Полезна команда диагностики/восстановления с проверкой процессов; автоматическое безусловное удаление вернёт прежнюю гонку.
3. **P2 — интеграционные сценарии обновления.** Добавить обновление при сохранённых вкладках, перезапуск VS Code и восстановление после прерывания. Две новые вкладки, названия и индикаторы уже проверяются, но это не эквивалент полного цикла обновления пользовательского окна.
4. **P2 — отдельная поддержка SSH и других платформ.** Проверен локальный Intel macOS. Windows, Linux, Apple silicon и удалённые окна требуют собственных проверок, включая взаимодействие локального дополнения с удалённым extension host.
5. **P3 — удобство индикатора.** Выбор «осталось/использовано», время до сброса и ненавязчивое предупреждение при малом остатке. Эти возможности пока не реализованы.
6. **P3 — большая история.** `readSessionNames()` читает весь индекс в память. Потоковое чтение пригодится для больших архивов; текущий индекс на момент проверки — 3609 байт, поэтому срочной проблемы памяти здесь не наблюдается.

Отдельные сообщения `ResizeObserver` ранее наблюдались в официальном интерфейсе Codex. Их причина не установлена; этот аудит не приписывает их дополнению и не заявляет об исправлении. Произвольную совместимость со всеми будущими версиями Codex гарантировать нельзя: неизвестные структуры по-прежнему должны проходить проверку до установки.
