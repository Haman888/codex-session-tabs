# Восстановление Codex после обновления дополнения — 13.11.2026

## Исправления 0.8.2

- Резерв предыдущей сборки теперь может пройти повторную проверку через команду восстановления. Проверяются SHA-256 архива, его пути и типы записей, версия, оригинальный и изменённый код Codex, нативный мост, при необходимости renderer, полное дерево распакованных файлов и интерфейс в отдельном VS Code. Запись о проверке обновляется только после успеха.
- Обновление Codex после смены дополнения сначала перепроверяет прежний резерв. Регрессия воспроизвела замену старого резерва новым кандидатом в 0.8.1; теперь прежний резерв сохраняется. Если он несовместим с новым дополнением, его запись сохраняется отдельно в `retained-recovery.json`, пакет защищён от очистки, а новый кандидат обязан пройти собственную полную проверку. Регрессия проверяет также сохранение отдельного пакета при следующем обновлении.
- Смена только `package.json.version` и служебных `__metadata` установки не отменяет проверку. Остальная конфигурация manifest, исполняемые файлы, переводы и тест интерфейса продолжают входить в отпечаток.
- Установка и восстановление повторно сверяют дополнение после диалога подтверждения. Два теста воспроизвели установку после изменения нативного моста, пока диалог был открыт; оба сценария теперь отказывают до установки.
- Записи о резерве и архивы, представленные символическими ссылками, отклоняются. При провале перепроверки прежние файлы остаются на месте.
- Команда статуса различает работающий PID блокировки, завершённый процесс и непроверяемое состояние. Она не удаляет блокировки; работающий PID не доказывает, что это прежний процесс, поэтому такая блокировка всегда сохраняется.

## Ограничения

Автоматическое снятие остаточного `operation.lock.reclaim` пока не реализовано: безопасная диагностика не равна разрешению удалить файл. Нужен отдельный протокол координации между окнами, включая старые версии дополнения.

При изменении нативного моста старый пакет может оказаться несовместимым. Перепроверка его отклоняет; команда обновления проверяет новый официальный пакет с текущим адаптером и сохраняет прежний резерв отдельно. Совместимость с произвольными будущими версиями Codex не гарантируется.

Windows, Linux, Apple silicon и удалённые extension host в этом проходе не проверяются. Счётчик до сброса недельного лимита и предупреждение о малом остатке остаются отдельными улучшениями.

## Интеграционные попытки

Первый прогон с внешним VS Code и двумя вкладками остановился на 180-секундном таймауте подготовки архива до установки. Во втором прогоне подготовка продолжалась медленно; он остановлен вручную по точным PID тестового окна и его процесса подготовки. На Mac наблюдалось 5771 МБ использованной подкачки. Это не успешные проверки восстановления вкладок.

Повторная проверка через `test/recovery-command.cjs` использует обработчик настоящей команды, подготовку и проверки из `update-ui.js`, один изолированный VS Code для штатных девяти проверок и настоящий CLI-установщик в отдельной папке расширений. Адаптер API VS Code у этого стенда заменяет диалоги и маршрутизирует установку в CLI; сохранение вкладок через перезапуск он не проверяет.

Подготовка резерва теперь имеет ограничение 10 минут и поддерживает отмену; убрано повторное чтение исходного архива перед копированием. Копия по-прежнему полностью проверяется по SHA-256 до распаковки и исполнения.
